# Руководство

FMA (Fractal Module Architecture) — skill для AI-агентов, работающих с Angular и NestJS; форк идеи FDA (`chord-ts/fda`). Добавляет необязательный слой `domain`, порты, события, общие контракты и автоматическую проверку правил.

Сам skill написан на английском, чтобы его можно было использовать с любым агентом. Справочники ниже тоже на английском; эта страница описывает, что внутри и как этим пользоваться.

## Установка skill

Скопируйте `skills/fma/` из [репозитория](https://github.com/Hooter/fma-skill) в `.agents/skills/fma/` (или `~/.claude/skills/fma/`) проекта.

## Как это работает

Агент загружает `SKILL.md`, затем справочник по типу приложения: [Angular](/references/angular) для `apps/web` или [NestJS](/references/nestjs) для `apps/api`.

- **Фрактальность:** структура модуля повторяется на уровне подмодуля и домена.
- **Слои:** `ui → state → api → model → repo`, плюс необязательный `domain` (ярус `rich`).
- **Публичный вход:** модуль виден соседям только через `index.ts`; `export *` запрещён.
- **Порты:** вызов соседей и внешних систем оформляется через порты. Доменный порт лежит в домене, инфраструктурный (события, часы, почта) — в `shared/<segment>`.
- **Ярусы:** `simple` по умолчанию; `rich` — когда в домене есть инварианты (признак: папка `domain/`).
- **Правила проверяются машиной:** `arch:check` запускает линтер, dependency-cruiser и Sheriff.

## Подключение проверки правил в проект

Два профиля инструментов, подробно в [Проверке правил](/references/enforcement) (на английском):

- **Базовый:** ESLint, Prettier, TypeScript 6. Работает везде.
- **Ускоренный:** oxlint, oxfmt, `tsc` 7. Подключается там, где работает.

Шаблоны из `skills/fma/templates/` копируются по таблице на этой странице. `arch:check` выбирает линтер флагом `--linter eslint|oxlint`.
